# 应急智航预设场景包

这是项目的场景配置与数据加载模块，不是完整的无人机仿真软件。九个JSON可作为Streamlit下拉框的数据源；完整引擎、预约和动画需按方案接入。

## 文件

- catalog.json：下拉菜单编号、名称和说明。
- S01.json～S09.json：包含完整地图、飞机、生成规则、固定任务和事件的预设。
- scenario_loader.py：标准库实现的加载、确定性任务生成、结构与引用检查。
- resolved/：seed=42展开后的九份完整输入，可直接审查任务清单。
- catalog_summary.md：场景说明和下拉交互要求。

## 展开场景

在本目录执行：

```text
python scenario_loader.py --scenario S03 --seed 42 --output my_scene.json
```

此命令只生成输入，不模拟飞行。无需额外Python依赖。materialize()不会修改原始配置；已经展开的数据再次加载不会重复生成任务。

## Streamlit接入示例

以下代码应放入现有界面，替换已有的场景输入区；engine_factory、pause、flush_logs由1号引擎提供，并非本包内函数。

```python
import streamlit as st
from scenario_loader import catalog, load_preset, materialize

items = catalog()
names = {x['id']: x['name'] for x in items}

def stage_change():
    engine = st.session_state.get('engine')
    if engine is not None:
        engine.pause()
    st.session_state['pending_change'] = True

sid = st.selectbox('模拟场景', list(names),
    format_func=lambda key: f'{key} {names[key]}',
    key='pending_scenario', on_change=stage_change)
cfg = load_preset(sid)
st.write(cfg['description'])
st.caption(cfg['observe'])
st.dataframe(cfg['events'])
strategy = st.selectbox('调度算法', cfg['strategy_choices'],
    index=cfg['strategy_choices'].index('G4'),
    key=f'pending_strategy_{sid}', on_change=stage_change)
seed = st.number_input('随机种子', value=42, step=1,
    key='pending_seed', on_change=stage_change)

if st.button('加载并重置'):
    try:
        resolved = materialize(cfg, int(seed))
        # 先构造并校验新引擎；创建新run_id和目录，严禁覆盖旧运行。
        new_engine = engine_factory(resolved, strategy)
        old_engine = st.session_state.get('engine')
        if old_engine is not None:
            old_engine.flush_logs()
        st.session_state['engine'] = new_engine
        st.session_state['loaded_scenario'] = sid
        st.session_state['pending_change'] = False
    except (ValueError, OSError) as exc:
        st.error(f'加载失败，旧运行仍保留：{exc}')
```

“自定义”界面可复制cfg后编辑或导入JSON，再调用materialize校验。前端的取值限制、额外参数校验与新run目录创建应由应用层补齐，本示例只说明下拉加载主链路。

## 引擎处理约定

1. tasks里的任务由release_s驱动发布。S02和S09的急救是固定任务，不另发新增事件，避免重复。
2. EDGE_CLOSE：禁止新增进入，允许在途驶离；EDGE_OPEN恢复。SET_ALLOWED_LAYERS同样采用驶离式禁用，地面和等待位不瞬移。恢复层时还要与策略允许层取交集。
3. LINK_LOSS：禁止新指令并保留不确定占用。CONFIRM_REMOVED：显式清空该机的占用，将其货物由在途转为确认损失；任务未满足量重新可派发。不能同时把丢失货物加回仓库。
4. TASK_CANCEL：仅取消未交付需求，携货飞机安全返仓后再归还库存。
5. bootstrap_deliveries在初始化时执行一次并记delivery_id。它表示场景开始前已发生的交付，在本场景t=0建账。计入库存与需求守恒，但排除本轮运输效率统计。
6. 生成任务每个有独立demand_id，表示互不重复的需求批次。相同site_id/cargo_type可能出现多个批次，不能因此合并或重复增加同一需求；同一需求增加数量需用其原demand_id更新。
7. 生成的截止时间等于发布时刻＋单机参考路线耗时＋余量；包含起降装卸，但不包含机队排队、换电和多批次等待，因此不是准时保证，也不是Dijkstra最短时间证明。S09刻意缩短余量。
8. 默认S01有20任务，S02有21，S09有31；总数始终显示生成任务＋固定任务。常规自定义最多30项，S09锁定压力预设特许31项。
9. S03/S06关闭B-D和C-E，使X成为左右两侧之间必经点；集中发布时间不能保证同秒抵达，是否换层由成本与预约决定。精确同时抵达的测试继续使用方案中的X06夹具。
10. S07的低电量机位于地面，预计能量不够应先换电；默认装卸位与换电维修位分离，换电每机独立，避免低电量机占住唯一装卸位。换电需120秒，不能立即充满。

仅S01/S02/S04/S05作为主实验四场景；S03/S06/S07/S08/S09用于功能演示和压力测试。比较时先冻结同seed的resolved输入，再分别运行各算法。
